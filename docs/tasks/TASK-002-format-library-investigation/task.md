## Recommendation and failure classification

**Repair test/build correctness and MP's Error API first. Track formatting modernization as a separate implementation task.** An upgrade offers long-term maintenance benefits but is not a demonstrated cure for the baseline failures.

| Finding | Evidence and implication |
| --- | --- |
| Integer error arguments retain placeholders | Direct bundled `fmt::format("answer {}", 42)` returns `answer 42`; `mp::Error("answer {}", 42)` yields `answer {}` and exit code 42. Error's non-template message/code constructor wins over its FMT_VARIADIC_ template for this call. This is an MP API selection defect, not failed integer formatting. |
| An upgrade alone cannot resolve that intent conflict | An isolated fmt 12.2.0 probe implementing the same message/code plus variadic constructor shape still yields `answer {}` and code 42. A rewrite to format_string might change conversion ranking or cause ambiguity, but it cannot define which meaning an identical `(message, int)` call intends. An explicit API decision is necessary. |
| Duplicate suffix crash depends on missing MSVC exception flags | Direct bundled formatting of `StringRef("foobar", 3)` returns `duplicate suffix 'foo'`; standalone suffix insertion catches that exact Error successfully with /EHsc. Original suffix-test reproduces SEH 0xc0000005. Recompiling its unchanged source with /EHsc and linking unchanged baseline mp/gtest-extra libraries passes all 26 cases. A separately compiled no-/EHsc target reproduces the crash. Adding only target /EHsc to that same configuration makes all 26 cases pass. |
| Missing /EHsc also affects code outside Google Test | A standalone no-/EHsc suffix probe prints the caught message and then exits with access violation -1073741819 (0xc0000005). Its /EHsc counterpart exits successfully. This controlled result identifies an exception-unwinding defect in the diagnostic configuration; it does not establish a production suffix defect or explain every other baseline crash. |
| Other baseline failures need their own repairs | Google Test's std::tr1 build blocker, BoolOption storage, fixture/mock drift, allocator expectations, and Windows death tests are not fixed by replacing fmt. TASK-001 remains the authority for its 12/21 baseline result. |

Crucial configuration distinction: the original build/ cache and a newly configured default project both have `/DWIN32 /D_WINDOWS /W3 /GR /EHsc`. Only build-unit-investigation lacks /EHsc: supplying `-DCMAKE_CXX_FLAGS=/DGTEST_USE_OWN_TR1_TUPLE=1` replaced, rather than appended to, CMake defaults. `support/cmake/init.cmake` installs configuration/runtime overrides, but they are not evidence of a missing default exception flag. The observed suffix crash is an artifact of that experimental global-flag replacement. Repair the diagnostic configuration/framework workaround and refresh results; no production suffix fix is justified by this evidence. Microsoft documents that omitting an exception model only partially supports C++ exceptions and may produce undefined behavior/resource leaks: [official /EH documentation](https://learn.microsoft.com/en-us/cpp/build/reference/eh-exception-handling-model?view=msvc-170). The experiment isolates /EHsc as sufficient for this suffix reproduction; no debugger stack trace or sanitizer result was obtained.

## Integration inventory and migration costs

CMake builds `format` as an OBJECT library from both headers and both sources; embeds its objects in `mp` and `gen-expr-info`; produces `format-dynrt`/`mp-dynrt` MSVC variants. Header installation copies include/mp. Modern dependency linkage must propagate to generators, libraries, installed consumers, and embedded builds. The helper's automatic `${lib}-dynrt` naming cannot be applied blindly to upstream `fmt::fmt`.

| Surface | Current uses and modernization work |
| --- | --- |
| Public strings and callbacks | StringRef/CStringRef occur in error, solver/output-handler, option, suffix, reader, OS, expression and SOL APIs. CStringRef promises c_str; string_view does not. Preserve lengths and termination with deliberate owned conversions where C APIs need them. Removing implicit std::string conversion may expose caller dependencies. |
| Output buffers and writers | MemoryWriter/Writer, write(), stream insertion, str(), data()/size()/c_str() appear throughout core, examples, tests, and drivers. Migrate to memory_buffer plus format_to/vformat_to/to_string or a bounded MP-owned adapter. format_to does not append a NUL terminator. Preserve lifetimes, append behavior and precision. |
| Variadic and erased argument APIs | FMT_VARIADIC/FMT_VARIADIC_ and ArgList are used by Error/UnsupportedError/ReadError, reader ReportError, BasicSolver Print/ReportError, and BARON, Gecode, JaCoP, SMPS helpers. Replace with variadic templates and synchronous format_args/make_format_args/vformat. Runtime format strings need runtime/vformat; do not retain dangling argument stores. |
| Custom formatting | ADL BasicFormatter hooks in expr.h/expr.cc cover NumericExpr and expression wrappers; BasicSolver::DoubleFormatter handles objective precision. Migrate to explicit fmt::formatter specializations or suitable format_as functions. Preserve expression precedence and objective precision/environment behavior; do not replace objective precision with the writer's max_digits10 policy. Review enum/int-convertible arguments under modern type checking. |
| Dependency internals | Error inherits fmt::internal::RuntimeError. safeint and NL reader use MakeUnsigned/is_negative/Yes/No; expr uses EnableIf; reader/OS/solver/ASL use internal MemoryBuffer, make_ptr, UTF8/UTF16 conversion. Replace with MP/std facilities and documented APIs rather than renaming internal to detail. Deleted-copy macros become ordinary deleted operations. |
| Files/system errors | File/BufferedFile/SystemError and POSIX macros support NL input, SOL output, OS tests, temporary files, generated sources and BARON. Modern system APIs live in fmt/os.h and error behavior/types differ; migrate ownership, close/dup/pipe/error-code handling and Windows paths deliberately. |
| Solver drivers | Broad fmt::format use plus concentrated writer/file/ArgList dependencies in BARON; Xpress writers; legacy ASL/Gecode/JaCoP/ILOGCP/SMPS integrations. Every enabled backend must rebuild; a core test pass does not validate unavailable SDK integrations or emitted solver syntax. |
| NL Writer | Search found no direct formatting dependency in standalone nl-writer2 except a suggestion in a comment. Its own numeric formatter uses to_chars or dtoa. Do not introduce an unnecessary fmt dependency there. MP reader/driver integration, especially mp2nl and writer/reader round trips, remains affected indirectly. |

Modern official API documentation supports formatter/format_as, format_args/vformat, memory_buffer/format_to, system APIs and separate printf/wide headers: [fmt API](https://fmt.dev/latest/api/). These are replacements requiring adaptation; replacing the four legacy files is not a supported drop-in migration. The source inventory is not a downstream consumer audit.

## Toolchain, dependency, ABI and license assessment

The inspected toolchain is VS 2022/MSVC 14.44.35207 in C++17 mode. Existing fmt builds but warns STL4043/C4996 for stdext iterators. MP already gates checked iterators off at _MSC_VER >= 1951; current compiler still uses the deprecated branch. Microsoft's removal is established in [STL PR 5817](https://github.com/microsoft/STL/pull/5817). This warning is distinct from std::tr1's fatal Google Test error. A small portable iterator-path repair can be considered independently; std::span would raise the C++ standard to C++20 and is not needed for the immediate repair.

Official [fmt portability documentation](https://fmt.dev/latest/) describes C++11/MSVC 2017 or newer support. The official releases page showed 12.2.0 as latest at investigation time: [releases](https://github.com/fmtlib/fmt/releases). Treat **pinned 12.2.0 as a tested candidate**, not an MP compatibility guarantee. Its three core headers compiled and ran with C++17 /EHsc /utf-8. Default MSVC encoding caused a Unicode static_assert failure; /utf-8 resolved it. /W4 emitted C4127 warnings in upstream headers, so strict warning-clean builds were not established. A /W4 /WX attempt without /utf-8 failed. No stdext iterator use was found in those three modern core headers; modern os/printf integration was not built.

Public fmt types, callback signatures, inline templates and writer layout make this a source and ABI migration. Current fmt is unversioned whereas modern fmt uses versioned internals; that alone does not make mixed headers safe. Include guards, FMT_ macros, namespace declarations and duplicate definitions require explicit single-version/coexistence tests. Rebuild all MP libraries and driver binaries together; do not mix old/new headers or object files. Evaluate /MT versus /MD and Debug/Release consistently, DLL exports/imports, PIC for shared targets, package installation and parent projects that already supply fmt. Existing specification leaves stable ABI policy open; a compatibility promise must be agreed before implementation.

| Upgrade approach | Assessment |
| --- | --- |
| Keep patched 3.0.1; targeted fixes | Smallest immediate risk and no new dependency. Fix Error/build issues directly; optional checked-iterator cleanup. Retains aging code and patch maintenance. |
| Move to another old fmt release | Potentially smaller intermediate API step, but still requires exact patch/behavior audit and leaves another upgrade. No old release was established here to cure the failures. Not recommended as the modernization destination. |
| Pinned modern fmt plus MP facade | Recommended modernization direction. Remove internal dependencies first and keep compatibility adapters limited and documented. Vendor a clean upstream subtree with recorded tag/hash and patch policy; prefer compiled upstream target. Offers deterministic/offline standalone builds while MP owns update and license maintenance. |
| Installed fmt via find_package | Useful opt-in for package/parent-project integration. Set and test a compatible version range, transitive usage/export/install dependencies and runtime linkage. Environment-dependent versions should not silently redefine output or ABI; missing package must give a clear configuration error. |
| FetchContent | Officially supported; pin immutable commit/archive hash and offer offline/local source override. Configure-time network availability and MP's older CMake minimum need review. Do not make unrestricted moving-branch downloads the default. |
| Header-only modern fmt | Supported alternate mode, useful for smoke tests; increases compile cost and embeds templates/macros throughout consumers. Does not avoid public API migration, encoding flags, or coexistence risks. |
| std::format | Not an immediate C++17 replacement; would require a separate standard/toolchain decision and file/printf/custom-formatter adaptations. |

Official [CMake integration guidance](https://fmt.dev/latest/get-started/) provides compiled/header-only targets and embedded, installed and FetchContent approaches. Recommend vendored pinned sources by default with an explicit external override, subject to maintainer agreement; do not build both implementations into one target graph.

Current four-file notices contain the older BSD-style two-condition license. Modern fmt uses the permissive [MIT license](https://github.com/fmtlib/fmt/blob/12.2.0/LICENSE). Retain the new license with vendored source/distribution, preserve notices for any retained legacy/derived code, and update packaging/license inventory. This is a notice-management task, not evidence of a licensing barrier.

## Prioritized implementation roadmap (proposed, not performed)

1. **Repair build correctness before dependency replacement.** Restore a test-scoped Google Test tuple setting or separately modernize the framework while retaining CMake default flags. The default build already enables /EHsc; fix the experimental global-flag replacement rather than inventing a production exception-flag defect. Verify exception support in fresh Debug/Release configurations for production, generators, tests and dynamic-runtime variants. Add a meaningful RAII-unwinding regression and rerun the complete suffix target. Audit cache overrides so an old cache cannot mask the fix. Address TASK-001 BoolOption storage separately; an fmt update does not repair it.
2. **Make Error intent explicit.** Lowest-risk immediate bridge: preformat affected integer-message call sites with fmt::format and use an intentional message/exit-code construction; preserve and regress required status mapping. Preferred durable API: a named/tagged explicit-code constructor/factory and unambiguous formatting entry point. Update MP_RAISE_WITH_CODE and all explicit-code callers atomically; audit direct Error calls, UnsupportedError/ReadError, copies and macros. Do not guess intent by scanning for braces, changing int to long, or choosing a fmt version by overload accidents. Keeping the old `(message, int)` overload retains the conflict, so deprecation/compatibility policy is consequential. Agree whether message-only -1 and formatted EXIT_FAILURE should remain distinct before changing defaults. Add integer, string, multiple arguments, literal braces, no-argument message, explicit code, infeasibility and solution-check status regressions. Existing error-test covers string formatting but misses integer/code ambiguity.
3. **Define modernization contracts and capture outputs.** Open a separate authorized implementation record. Decide supported compilers, source/ABI policy, facade extent, dependency provider, encoding, numeric precision and formatting exception translation. Capture public expression/objective/help/diagnostic/SOL/SMPS/BARON outputs plus difficult numeric values. Update specification and public migration notes when these contracts are accepted.
4. **Remove dependency on legacy internals, then swap engine.** Convert traits, buffers, copy-deletion and UTF conversion to owned/std/documented facilities in reviewable steps. Migrate strings/argument lifetimes/writers/file wrappers and the expression/objective formatters. Integrate pinned modern fmt with correct PUBLIC usage requirements, generators, static/dynamic runtimes, installation and external-provider tests. Preserve explicit max_digits10 where model serialization needs it; shortest-round-trip output may preserve values while changing golden text. Keep unrelated solver transformations out of this migration.
5. **Validate components, drivers and distribution.** Fresh standalone and embedded Windows Debug/Release C++17 builds; available GCC/Clang and Windows new-STL builds; full CTest plus compulsory converter-flat-test/converter-mip-test. Run error/suffix/expr-writer/solver/NL-reader/os/option/SOL tests with no exclusions and compare failure deltas against the baseline. Add negative formats, lifetime/NUL/nonterminated strings, Unicode paths, locale changes, signed zero, subnormals, huge/small values, NaN/Inf and precision regressions; use numerical tolerances and round-trip checks where appropriate. Use MSVC ASan or Unix ASan/UBSan for allocation/unwinding/lifetime paths; verify file errors and empty/partial writes. Build gen-expr-info/examples, independent installed-header consumers, shared/runtime variants and modern-fmt coexistence configurations. Build standalone NL Writer C/C++ examples and its normal package/wheel checks; exercise public text/binary writer-reader/SOL round trips and mp2nl.
6. **Gate real-driver delivery on applicable evidence.** Build affected available drivers, especially BARON emitted models and Xpress writers; run representative end-to-end models covering objectives, options, diagnostics, statuses, suffixes and numerical serialization, with documented solution-checker configurations. Use a separate copied fixture/output location to preserve original artifacts. Enumerate missing SDKs/licenses and skipped cases instead of treating core builds as driver certification. Complete release/CI/package checks after correctness is restored; modernization is not complete merely because fmt's smoke probe passes.
